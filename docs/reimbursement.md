# 报销材料识别与代办

实际报销人是费用归属人，经办人是负责整理、上报材料的人。两者可以不同；缺少实际报销人时可先存草稿，稍后补充。经办人默认取工作台个人设置中的姓名，报销人、电话和收款账户不会自动套用个人设置。

新建报销可一起上传发票、支付记录、行程单和 TXT。TXT 支持 UTF-8、UTF-16（含大小端）和 GBK / GB18030，单份最多 1 MB。带有标签的内容可以自动填写：

```text
报销人：示例甲
经办人：示例乙
报销事项：活动交通
同行人：
1. 示例丙
2. 示例丁
起点：学校南门
终点：活动会场
```

简繁体的同行人标签、多行名单均可识别。若文件名含“同行”或“同乘”，也支持文件内容仅包含姓名名单。付款人、乘客姓名不会直接当作实际报销人。明确标注的“报销人收款银行”“报销人收款账号”可以自动填写；发票商家的开户行不会当作报销人的收款信息。

行程单支持起终点、上下车地点、标签和值分行及表格列。发票按购买方和销售方区域提取名称、税号，支持双栏顺序颠倒及 PDF 中的竖排区域标记。多条不同路线或无法明确区分的抬头会提示核对，不采用第一条或商家名称猜填。

详情页继续补充上传时，会填入空白身份、同行人及起终点字段，保留已有编辑。TXT 原件会保留在 ZIP，材料清单和 Excel 使用对应的 TXT 文件名；TXT 不参与 PDF 合并。

列表和详情均有删除入口。确认后删除报销记录、附件、已生成的材料包，关联事务保留。

验证命令：

```sh
pnpm build
node scripts/check-reimbursement-text.mjs
node scripts/check-recognition.mjs
node scripts/smoke-test.mjs
node scripts/check-security.mjs
```

测试只使用虚构材料及隔离数据目录。
